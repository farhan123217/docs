GBP Auditor uses a single, consistent design system across the popup, side panel, dashboard, and floating button. All visual decisions are expressed as Tailwind CSS tokens and reusable React components so the UI remains predictable as the product grows.

## Design tokens

Tokens are implemented as Tailwind theme extensions in `tailwind.config.ts`. All values are static strings (no dynamic JS) so Tailwind can purge unused styles at build time.

## Dark mode strategy

Dark mode uses the `class` strategy. The root element of each mount point (popup, side panel, dashboard iframe) receives `class="dark"` when the theme is set to dark or when the system prefers dark and the theme is set to `"system"`.

```tsx
// src/hooks/useTheme.ts (proposed/spec)
export function useTheme() {
  const [theme, setTheme] = useState<'light' | 'dark' | 'system'>('system');

  useEffect(() => {
    const root = document.documentElement;
    const isDark =
      theme === 'dark' ||
      (theme === 'system' && window.matchMedia('(prefers-color-scheme: dark)').matches);
    root.classList.toggle('dark', isDark);
  }, [theme]);

  return { theme, setTheme };
}
```

Color tokens are defined for both modes using the `{ DEFAULT, dark }` pattern. Utility classes like `bg-page text-text-primary` work in both themes because the values swap automatically when the parent has `.dark`.

## Shared components

Components are organized under `/src/components` and follow a single-responsibility rule. Props use strict TypeScript interfaces. No component exceeds ~250 lines; complex layouts decompose into smaller sub-components.

### Component list

| Component | Responsibility |
| --- | --- |
| `AppShell` | Layout wrapper with theme class, font, and base padding |
| `Sidebar` | Collapsible navigation for the dashboard and full pages |
| `Topbar` | Title, breadcrumb, and global actions (export, settings) |
| `Popup` | Root layout for the ~400px extension popup |
| `FloatingButton` | The `[GBP]` button injected into Maps pages; position, visibility, and z-index |
| `SidePanel` | 320–450px panel with header, tabs, and collapse/expand/close controls |
| `BusinessHeader` | Business name, rating, review count, and category badge |
| `ScoreCard` | Large circular or linear score display with color-coded ring |
| `AuditCard` | A card for an audit section with title, score, and issue list |
| `MetricCard` | Small card for a single metric with label, value, and optional change indicator |
| `IssueCard` | A single issue row with status icon, label, and explanation |
| `OpportunityCard` | Issue title, why it matters, and suggested action |
| `DataTable` | Responsive table with horizontal scroll, sortable headers, and row actions |
| `CategoryBadge` | Styled badge for primary or additional categories |
| `RatingBadge` | Star rating display with numeric value and review count |
| `StatusBadge` | Small badge for PASS / WARNING / MISSING / OPPORTUNITY states |
| `SearchBar` | Input with icon, clear button, and optional debounced onChange |
| `FilterBar` | Horizontal list of filter pills with active state |
| `Tabs` | Accessible tab list with keyboard navigation and aria roles |
| `Modal` | Centered overlay with focus trap, escape to close, and action footer |
| `Drawer` | Slide-in panel for mobile or secondary detail views |
| `Tooltip` | Hover-triggered info bubble using native `title` or a custom portal |
| `EmptyState` | Illustration, message, and call-to-action for empty lists |
| `LoadingSkeleton` | Placeholder blocks for cards, tables, and text while data loads |
| `ExportButton` | Dropdown button with print, CSV, JSON, and copy actions |
| `Pagination` | Page numbers and previous/next for long tables |
| `ConfirmDialog` | Modal with destructive confirmation pattern and cancel button |

## Responsive sizes

The extension targets three canonical widths:

- **Popup**: 400px wide, height auto up to 600px
- **Side panel**: 320px (compact) to 450px (expanded), full viewport height
- **Dashboard / full pages**: responsive from 768px upward; tables scroll horizontally on narrow viewports

All components use relative units and Tailwind responsive prefixes (`md:`, `lg:`) where needed. The side panel and popup do not support breakpoints below their fixed widths; instead, they rely on internal scrolling and compact component variants.
